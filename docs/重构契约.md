# 重构契约（三层边界）

本文件是本次重构的唯一权威约定。任何一层越界，都按"违规"处理，不做例外。

---

## 1. 四层与职责

```
┌──────────────────────────────────────────────────────────────┐
│ 视图层  scenes/**/*.gd + *.tscn                               │
│ · 节点布局、控件赋值（文本/图标/显隐/列表渲染）、切场景         │
│ · 把控件交互原样转发给桥                                       │
│ · 不算：数值比较、颜色推导、条目过滤、结局推演、进度换算        │
└──────────────────────────────────────────────────────────────┘
                    ↕  Godot Variant（Dictionary / Array / int / String）
┌──────────────────────────────────────────────────────────────┐
│ 桥层  src/bridge/*.cs                                         │
│ · UiBridge（autoload "UiBridge"）：唯一的 Godot 侧入口         │
│ · 只做：信号收发、Variant ↔ C# 类型转换、分派表查表             │
│ · 不算：任何公式、条件分支、默认值兜底、数据修补                │
└──────────────────────────────────────────────────────────────┘
                    ↕  纯 C# 调用
┌──────────────────────────────────────────────────────────────┐
│ 逻辑层  src/logic/*.cs（纯 C#，不引用 Godot UI 控件）          │
│ · GameHost：持有原版 GlobalScript / GameState，驱动时间推进     │
│ · Panes/*：面板快照装配（可含判定，但只调用原版，不重写公式）   │
│ · Port/*：移植适配（开局初始化、存档、运行时守护）              │
│ · Stub：替身工厂，让原版 MonoBehaviour 在无渲染环境下完整执行   │
└──────────────────────────────────────────────────────────────┘
                    ↕  直接调用
┌──────────────────────────────────────────────────────────────┐
│ 原版层  src/original（规则内核，只读）+ src/compat（Unity 桩） │
│ · 全部数值、事件、时间、存档读档、结局判定                    │
└──────────────────────────────────────────────────────────────┘
```

### 为什么有 `src/logic` 这一层

原版 C# 是"UI 驱动"的：每个界面脚本在 `OnMouseDown` 里既跑规则又把结果写进
`TextMesh`。要让视图层保持纯粹，必须有人在中间把"原版脚本算出来的东西"取出来。
这个人就是逻辑层——它属于**原版逻辑层的延伸**，不属于桥。

判定口径：

| 代码内容 | 归属 |
|---|---|
| `state.data[23] / 5` 这类换算（原版脚本里原本就算） | 原版层（不改） |
| "这一条要不要显示""按钮能不能点" | 逻辑层（调用原版判定或读原版算好的字段） |
| `Dictionary` → `Godot.Collections.Dictionary` | 桥层 |
| `if value > 100: color = red` | **违规**（视图层） |
| 在桥里兜底 `?? 0`、`catch` 后造数据 | **违规**（桥层） |

## 2. 通信协议

### 2.1 快照（逻辑层 → 视图层）

桥发射：

```gdscript
signal panel_snapshot(panel: String, data: Dictionary)
```

视图层请求：

```gdscript
UiBridge.request("概览")
```

快照内容全部由逻辑层装配，键名固定（见各面板说明）。视图层只读键、不做推断。

### 2.2 动作（视图层 → 逻辑层）

```gdscript
UiBridge.act("概览", "翻开下一页", [])
UiBridge.act("外交", "查看国家", [国家索引])
```

桥层只做 `panel/action` 查表分派 + 参数转换；查不到就报错返回，**不猜、不兜底**。

### 2.3 场景与提示（逻辑层 → 视图层）

```gdscript
signal scene_requested(path: String)   # 原版 SceneManager.LoadScene 的落点
signal toast(text: String)             # 需要玩家看到的一句反馈
```

视图层收到 `scene_requested` 才 `change_scene_to_file`；原版逻辑不直接碰 Godot 场景。

### 2.4 帧更新

`UiBridge` 每帧（或每 0.25s）对比一次逻辑层版本号，版本变化才发快照，避免视图轮询。

## 3. 视图层硬性禁令

1. 不写 `if` / `match` 判断游戏数值大小、阵营、年代、结局走向。
2. 不做加减乘除换算（百分比、涨幅、预测值全部由逻辑层给）。
3. 不读 `gs.gameState.xxx` 深层字段。视图层只允许出现：`UiBridge`、`get_node`、控件赋值、
   `change_scene_to_file`、纯 UI 动画/布局。
4. 颜色不自己推：逻辑层给 `Color` 或语义枚举（如 `"red"/"green"/"gray"`）。
5. 列表条目不自己过滤：逻辑层给"已经筛好的数组"。

## 4. 桥层硬性禁令

1. 不写业务公式（含"顺手算个百分比"）。
2. 不写条件分支决定游戏语义（`if (state.data[..] > x)`）。
3. **禁止任何保护性代码**：不许 `try/catch`、不许判 `null`、不许给默认值、不许做越界检查。
   缺字段、缺节点、缺资源一律让异常直接抛出——原游戏没有 Bug，会抛就说明装配缺件，
   要在启动日志里看见它，而不是被兜底掩盖。
4. 不做数据修补（改原版字段、改文案、补空数组）。
5. 桥层文件里出现 `new Decision(...)`、`state.data[..] = ..`、`GameBootstrap.` 一律视为越界。
6. 桥层只做：信号收发、Variant 与 C# 类型互转、面板/动作查表分派。

## 4.1 视图层硬性禁令（补充）

1. **禁止用 GDScript 生成 UI**：不许 `Label.new()` / `Button.new()` / `add_child` 拼界面、
   不许代码里设布局与尺寸。所有控件必须在 `.tscn` 里预置；
   列表渲染只用 `.tscn` 中已有的固定节点池（按需显隐 + 赋值），
   确需子控件时只能 `instance` 已有 `.tscn`。
2. **禁止保护性代码**：不许判 `null`、不许 `if node == null: return`、
   不许 `get_node_or_null` 静默降级、不许给默认值兜底。
   节点名写错就让 Godot 报错，暴露给人改。

## 6. 系统界面例外

以下界面**不对接原游戏逻辑**，纯 GDScript 实现（无桥调用）：

- 主菜单（`scenes/主菜单`）
- 设置（`scenes/设置`，含音频面板）
- 存档 / 读档列表页（`scenes/存档`，仅"读取槽位元信息"与"执行存/读"经桥）
- 关于（`scenes/关于`）

这些界面的持久化使用 `UISettings` / `AudioSys` / Godot `ConfigFile`，不读写原版 `GameState`。

## 7. 命名与文件约定

| 层 | 目录 | 命名 |
|---|---|---|
| 桥 | `src/bridge/` | `UiBridge.cs`（门面）、`UiBridge.<面板>.cs`（分派表）、`UiVariant.cs`（类型转换） |
| 逻辑 | `src/logic/` | `GameHost.cs`、`Stub.cs`、`Panes/<面板>Pane.cs`、`Port/<职责>.cs` |

## 9. 地图界面约定

`scenes/地图/地图.tscn` 已按原 Unity 场景搭建完成（259 块可拖拽节点、南美并入主世界、
国家图与 parts 分裂块齐全、战争图标节点齐全）。因此：

1. **不重排、不改节点结构、不改 `.tscn`**；只改 `.gd` 与逻辑层。
2. 着色：逻辑层用 `CountryScript` 替身跑原版 `Repaint`，读回
   `SpriteRenderer.material.GetColor("_MainColor")` / `"_MainColor2"`，
   视图层只 `material.set_shader_parameter` / `modulate` 赋值。
3. 领土分裂块显隐：读原版 `Country.parts[]`（逻辑层给出 `visible`）。
4. 战争图标显隐：调原版 `at_war_script.Repaint`，读回 `sprite == null` / `activeSelf`。
5. 点击坐标的命中判定由逻辑层完成（原版 `CountryScript` 用碰撞体命中），
   视图层只把 `(x, y)` 交给 `UiBridge.act("地图", "点击", [x, y])`。

## 10. 刷新约定

- 视图层需要随时间的界面（外交日期、顶部状态栏）自行用 `Timer` 定时
  `UiBridge.request(面板)`；频率建议 0.25–0.5s。
- 逻辑层不自动推送：原版很多取值方法带副作用（例如 `modify_choose.OnMouseDown`
  会写 `Country.spec`），高频自动刷新会改变游戏状态。只在视图需要时取值。
