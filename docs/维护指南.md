# 维护指南：不用 AI 也能改这个项目

本文件写给"接手这个仓库的人类程序员"。目标：看完能自己读代码、改逻辑、加面板、发版本，
不需要再让 AI 生成一遍。

---

## 0. 先弄懂这个项目是什么

原版《中国：毛的遗产》是 Unity + C# 的单机游戏（改版基于 1.132，改版本身基于 1.6.7）。
本仓库把它的 **逻辑层原样搬进 Godot 4.7**：

- 原版 C# 代码（反编译 → 重排版）基本不动，只替换引擎相关部分；
- 引擎 API（`UnityEngine.*`）由 `src/compat` 里的兼容层模拟；
- Godot 只负责"显示 + 输入"，所有游戏规则仍在 C# 里跑；
- 中间有一层薄薄的 `src/bridge/UiBridge.cs`，把 C# 的面板快照/动作翻译给 GDScript。

### 三层边界（铁律，改动前先问自己在哪一层）

| 层 | 位置 | 允许做 | 禁止做 |
| --- | --- | --- | --- |
| 原版逻辑层 | `src/original/` | 原版规则、数值、存档、事件、时间推进 | 引用 Godot 类型 |
| 兼容层 | `src/compat/` | 用纯 C# 模拟 `UnityEngine` API | 写游戏规则 |
| 移植逻辑层 | `src/logic/` | 装配替身对象、调原版、把结果整理成快照 | 复制原版公式/条件 |
| 桥层 | `src/bridge/` | 参数转换、入口转发、信号发射 | 判断数值、兜底、修数据 |
| 视图层 | `scenes/**.gd` | 布局、赋值、信号转发、切场景 | 算数值、推结局、改 GameState |

判断标准：**如果这行代码里出现"游戏规则"（阈值比较、加成公式、条件分支决定结局），
它就不该在 bridge 或 .gd 里。**

## 1. 必须掌握的 C# 知识点（按本项目实际使用频率排序）

### 1.1 语言基础

- **类、命名空间、程序集**：全部源码编译进一个程序集（`中国-毛的遗产[godot二版].csproj`）。
  `internal` 在同程序集内可见——本项目大量依赖这一点（如 `KGWars.Wars` 是 internal）。
- **`partial class`**：Godot 的 C# 脚本必须写 `public partial class X : Node`，因为引擎会用
  源生成器给同一个类补 `InvokeGodotClassMethod` 等成员。
- **静态类 / 静态字段**：`GameHost`、`Automation`、`DataSlots` 都是纯静态。
  注意静态字段的初始化时机：`GameStateFactory.模板实例` 是"第一次访问该类时"构造的。
- **属性与自动属性**：`public static int Launched { get; private set; }`。
- **结构体 `struct`**：`ShortcutPane.Entry`、`Automation.快照`。struct 是值拷贝，
  传参常用 `in`（如 `Diff(int index, in 快照 before)`）。
- **值类型 / 引用类型**：`data[]` 是 `int[]`（值拷贝），`Country`/`Politic` 是 class（引用共享）。
  存档、去重、模板复制都在利用这个差异。
- **`switch` 表达式**：`static string 归一(string text) => text switch { ... };`（C# 8+）。
- **模式匹配**：`case bool b: ...; case int i: ...;`（`SaveService.Write` 里就是）。
- **范围索引 / 切片**：`text[..sep]`、`parts[^1]`、`text[..24]`。反编译代码里的
  `array[^1]` 很常见。
- **目标类型 `new()`**：`private static readonly List<object> Lines = new();`。
- **空合并 / 空传播**：`??=`、`?.`、`?? ""`。
- **字符串插值**：`$"[{slot}] {name} = {value}"`。
- **`System.Array` 静态 API**：`Array.CreateInstance`、`Array.Copy`、`GetValue/SetValue`。
  存读档与数组扩容全靠它。

### 1.2 委托、事件、LINQ

- **`Action` / `Func<T>`**：原版决策与焦点系统大量用 `Func<bool>` 做条件、`Action` 做效果
  （`Decision.condition`、`Decision.active`）。看懂这两个字段就看懂了整个决议系统。
- **`event`**：`UiEvents.SceneRequested` 等。逻辑层发事件，桥层订阅后转成 Godot 信号。
  新增"逻辑 → 视图"的通知就在这里加一条事件 + 桥层一行订阅。
- **lambda 与闭包**：`() => GlobalScript.inst.gameState.data[21] < year`。
  注意闭包捕获的是**变量引用**，循环里捕获循环变量会出错。
- **LINQ**：本项目用得很少（性能敏感），主要用 `List/Dictionary/HashSet` 的手写循环。
  能读懂 `foreach`、`Contains`、`TryGetValue` 即可。

### 1.3 反射（本项目的关键技能）

反编译代码里字段几乎全是 `private`，移植层靠反射读写它们：

```csharp
const BindingFlags Flags = BindingFlags.Instance | BindingFlags.Public | BindingFlags.NonPublic;
typeof(TimeScript).GetField("global2", Flags).SetValue(Clock, state);
typeof(CountryScript).GetMethod("OnMouseDown", Flags).Invoke(set.Probe, null);
typeof(DiploButtonScript).GetField("uslovie_bool", Flags).GetValue(button);
```

- `GetField / GetMethod / GetProperty` 需要 `BindingFlags`；
- `Invoke` 调私有方法（原版 `Awake/Update/OnMouseDown` 都是 private）；
- `Activator.CreateInstance(type)` 造对象（要求无参构造，`Leader` 就没有）；
- `Assembly.GetTypes()` 枚举类型（调试台按 `Event([0-9]+)` 找事件类）；
- 反射出错的表现通常是 `NullReferenceException` 或 `MissingMethodException`，
  看到栈里 `System.Reflection` 就要想到"字段名/方法名写错了或对象没造"。

### 1.4 Godot C# 集成

- **`Node` 生命周期**：`_EnterTree`（最早，注册信号）→ `_Ready` → `_Process(double delta)`。
  本项目 `UiBridge` 在 `_EnterTree` 里 `AddUserSignal`，在 `_Ready` 里启动内核。
- **自定义信号**：`AddUserSignal("panel_snapshot", new Godot.Collections.Array { "panel", "data" })`
  + `EmitSignal(...)`；GDScript 侧 `UiBridge.connect("panel_snapshot", 回调)`。
- **跨语言类型**：`Godot.Collections.Dictionary/Array` 与 C# 字典/列表互转集中在 `UiVariant.cs`。
  往 GDScript 传 `long` 更安全（GDScript 的 int 是 64 位），接收时写 `(int)(long)args[0]`。
- **`CallDeferred("change_scene_to_file", path)`**：不能在信号回调里直接切场景。
- **`GetTree().CurrentScene`**、`SceneFilePath`：判断当前场景。
- **`Godot.ConfigFile`**：读写 `user://playerprefs.ini`（设置项都在这里，与 GDScript 的
  `UISettings` 共用同一文件）。
- **`Godot.Time.GetTicksUsec()`**：分帧节流（自动化、地图扫描每帧限 3ms）。

### 1.5 构建与工具链

- **Godot.NET.Sdk 4.7.2** + `net8.0`（Android 是 `net10.0`，见 csproj 注释）。
- 编译：`dotnet build`。产物在 `.godot/mono/temp/bin/Debug/`，Godot 编辑器热重载。
- 反编译代码的警告（CS0114/CS0108 等）已在 `NoWarn` 里静音，不要试图"修"它们。
- 版本号三处一致：`project.godot` 的 `config/version`、`site/version.json` 的 `version`、
  csproj 的 `Version/InformationalVersion`；`tools/check_version.py` 会校验前两处。

## 2. 本项目到底怎么跑起来的

### 2.1 启动链

```
场景树里的 UiBridge(Node)
   _EnterTree  注册所有用户信号
   _Ready      GameHost.SetDifficulty → GameHost.Boot()
                  GlobalScript.Init() → GameStateFactory.Fill → StartNewGame(1)
                  → GameStartScript.OnMouseDown（读 data/*.txt，建国家/政客/文本表）
                  → CreateDecisions → TimeHostFactory.Create()（造时钟与场景替身）
   _Process   GameHost.Tick(delta) + 差分信号
```

`GameHost` 是逻辑层唯一"总调度"：开局、读档、每帧推进、自动存档、战争去重都在这里。

### 2.2 替身机制（本项目最核心的技巧）

原版 Unity 脚本都是 `MonoBehaviour`，靠 Unity 序列化注入兄弟对象。
移植版没有 Unity，于是用 `Stub`（`src/logic/Stub.cs`）造"假 GameObject + 组件"：

- `Stub.Take<T>("名字", Lifecycle.X)`：取或造一个替身组件；
- `Lifecycle.Scene / Lazy / None`：决定原版 `Awake/Start` 什么时候跑；
- `stub.Set("字段", 值)` / `stub.Invoke("方法")` / `stub.Typed<T>()`，全部走反射。

**记住一个判断**：报"空引用"时先看这个对象是不是替身、字段有没有 `Set` 过、
`Activate()` 有没有调用（`Awake` 没跑 → 内部字段还是 null）。

### 2.3 面板（IPanel）模式

逻辑层每个界面都实现 `IPanel`：

```csharp
public sealed class FooPane : IPanel
{
    public string Name => "Foo";                       // 与 GDScript 的 const 面板 一致
    public Dictionary<string, object> Snapshot();      // 数据 → 视图
    public void Act(string action, List<object> args); // 视图 → 动作
}
```

- 注册：`PanelRouter.RegisterAll()`（`GameHost.Boot` 里调用）；
- GDScript 侧：`UiBridge.request("Foo")` 拉快照、`UiBridge.act("Foo", "动作", [参数])`，
  监听 `panel_snapshot` 拿数据；
- 快照用 `PanelSnapshot().Put(...).Build()` 拼，值只放基础类型/列表/字典。

**新增一个界面**：写 Pane → 注册 → 写 `.tscn`（控件全在场景里）→ 写 `.gd`
（只做赋值/转发）→ 在导航或按钮处 `UiBridge.request`。

### 2.4 自动化（`src/logic/Automation.cs`）

- 触发：`GameHost.Tick` 每帧调用；月份变化时开一轮，按 12 国/帧扫描；
- 数据来源：`DiploHost.Show` 返回原版按钮的 `is_active` + `uslovie_bool`，
  全 true 才调 `DiploHost.Activate`——**不复制原版判定**；
- 开关：`Categories`（按按钮 type，逐条勾）+ `DiplomacyGroups`（贸易/经济/联盟三组）；
- 会切场景/开战的 type 不入 `Categories`；只跑"安全分支"的用 `分支不切场景(type)` 再筛一次；
- 每轮结束写 `RoundSummary` + `Recent` 明细（国家 · 动作 · 资源差值），经
  `UiEvents.ReportAuto` → `UiBridge.auto_report` → 外交场景的「自动提示」控件；
  屏幕提示的开关是 `playerprefs [ui] auto_report`（设置·自定义页「自动动作提示」），
  关掉只影响弹窗，控制台 `auto` 仍能看全部明细。

**加一个新的自动按钮**：确认它在 `DiploButtonScript.Show` 里有 `is_active` 门禁、
执行分支不 `LoadScene` 不开战 → 把 type 加进 `Categories` → 国家面板上点勾即可。

### 2.5 存档

- 移植版格式：`SaveService` 反射遍历 `GameState` 写二进制（保留共享引用）；
- 原版 Unity 存档导入：`UnitySaveImporter` + `NrbfReader`（BinaryFormatter 兼容读）；
- `GameHost.ReplaceState` 是读档总入口：先 `EnsureCapacity` 补齐旧口径数组，
  再执行原版 `LoadInScript` 的读档后处理（重载文本表、重建决策）。
- 存档槽：`SavePaths`；自动存档：`GameHost.MaybeAutoSave`（每月/半年 1 号）。

### 2.6 调试控制台（最常用的排查工具）

游戏内 F12 或外交界面「控制台」按钮。命令实现在 `src/logic/panes/DebugPane.cs`：

- `data`：200 个槽逐段列出（名称来自 `Port/DataSlots.cs`）；`data 8 9999` 改写；
- `field`：`data` 之外的任意字段，支持 `a.b[3].c` 路径与 int/bool/byte/float/string；
- `auto`：看最近自动动作与资源消耗；
- `event n [选项]`：强制触发事件并结算；
- `ideo / terr / pol / fac / doctr / mods / wars`：各类诊断；
- `save/load/cheat/gold/pop`：存档与作弊。

改完代码不看日志就能验证的手段：**开控制台敲命令**，比重新读档快。

## 3. 常见改动怎么做（配方）

### 3.1 改一个界面文字

1. `scenes/<界面>/<界面>.tscn` 里找控件；
2. 文字若来自逻辑层快照，就在对应 `Pane` 里改；若是静态文字，直接改 `.tscn`；
3. **不要在 `.gd` 里拼业务文案**。

### 3.2 调一个数值

先判断它是 `data[]` 还是对象字段：
- `data[n] = x`（控制台 `data n x`）；
- `allcountries[i].xxx`（控制台 `field allcountries[i].xxx`）；
- `empires[i].xxx` / `politics[i].xxx` 同理。
改完记得看地图/面板是否刷新（`MapPane.Touch()` 或重新 request 快照）。

### 3.3 加一个设置项

1. `.tscn` 加控件（用 MCP 或编辑器）；
2. `.gd` 里 `UISettings.get_int/set_int(...)` 读写 `user://playerprefs.ini`；
3. 需要逻辑层感知的，在 `UiBridge` 加一个方法转发，逻辑层在 `_Ready`/开局时读取——
   **逻辑层不读配置文件**，只接受桥层推来的值。

### 3.4 修"多出来一份"这类 bug（欧加登战争就是范例）

思路：
1. 找到是谁在"追加"（原版 `War.DecleredWar` 往 `ingamewars` 末尾写）；
2. 找到去重依据是否稳定（曾经按"战名+双方"判断，但战争面板把战名就地翻译成中文，
   存档里那条和新追加那条名字不一致 → 去重失效 → 列表出现两场）；
3. 修法优先级：**让数据不被视图污染** > 在入口处去重 > 在显示处兜底；
4. 加一个可复现的观察点（控制台 `wars` 命令列出所有进行中战争）。

### 3.5 发版本

1. 改三处版本号 + `site/version.json` 的 notes；
2. `dotnet build` 通过；
3. 导出（Android 有专门的 csproj 注释，走 NativeAOT 配方）；
4. 更新 `site/version.json` 上传（主菜单启动会自动检测并提示加群）。

### 读原版代码的三个窍门

1. **先看 `Show` 再看 `OnMouseDown`**：前者决定按钮显示与条件，后者是实际效果；
2. **文案即证据**：`this_opis = "..."` 旁边就是这行逻辑的业务含义；
3. **grep 是最好的文档**：`grep -rn "关键词" src/original --include=*.cs`；
   找不到就搜中文文案（原版文案多为中文/俄文双语）。

## 5. 排错速查

| 现象 | 先查什么 |
| --- | --- |
| `NullReferenceException` 在 `System.Reflection` 附近 | 替身字段没 `Set`、`Awake` 没跑、对象没造 |
| 界面空白但没报错 | 面板 `Name` 与 `.gd` 的 `const 面板` 不一致；信号注册晚于 `_ready` |
| 时间不动 | `okno.active` 被置 true（`SpeedScript` 判定）；`GameHost.SetMainScene` 是否在推进 |
| 读档后数组越界 | `GameStateFactory.EnsureCapacity` 是否覆盖该数组；旧档口径 |
| 焦点/事件重复触发 | 进程级静态单例（`Wars.O` 之类）与存档对象不是同一引用 |
| 手机上按钮没了 | 检查 `OS.has_feature("mobile")` 分支里有没有被 `visible = false` |
| 修改没生效 | 按错了对象：`data[7]` 是缓存，真值是 `influencePRC`；`completedDecisions` 会被月度复位 |

## 6. 不要做的事

- 不要改 `src/original` 里"看起来多余"的反编译产物（如 `_ = x;`、重复赋值），它们是原版行为。
- 不要在 bridge/`.gd` 里写数值判断与兜底——这类"业务补丁"一旦出现就会在别处产生不一致。
- 不要在 `.gd` 里用 `Control.new()` 造界面，控件必须来自 `.tscn`。
- 不要用"临时文件"放项目目录或 C 盘。
- 不要在没看源码的情况下"猜"索引和编号；先 grep，找不到就问项目所有者。
